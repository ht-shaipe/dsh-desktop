01 功能特性

不是简单的"套壳浏览器"，而是一个真正可交付给非技术用户的桌面应用。

⚡

开箱即用

双击 App，自动运行 npx -y @deepseek-ai/dsh web，无需手动敲命令、无需装 Node。

🖥️

内置交互终端

实时显示命令输出（彩色、进度条、光标移动），底部输入框可手动回复确认提示，行为与真实终端一致。

🤖

智能自动应答

检测到 (y/N) 确认时自动回复 y，黄色横幅原样展示问题文字；用户手动输入后立即交还控制权。

🔍

环境自检 + 便携 Node

启动前逐项检测环境；Node 缺失或版本过低时，自动从国内镜像下载便携版 v22，零额外配置、无需管理员权限。

🔄

应用内自动更新

标题栏一键"检查更新"，自动从 GitHub Releases 下载并原地替换；minisign 签名校验，防篡改。

🧹

干净退出 + 端口自清理

关窗即 killpg 杀掉整个进程组；残留进程占用 3080 端口时启动前自动识别并清理。

💊

帮助窗口 / 原生提示

标题栏常驻"帮助"按钮，独立窗口展示使用说明；更新完成等状态用系统原生 Toast 通知。

📦

自包含二进制

HTML / JS / 图标全部 include_str! 编译期内嵌，产物完全自包含，各平台只需分发二进制本身。

02 工作原理

从双击到看到界面，中间发生了什么？

环境自检 → 打印检测清单（✓/✗），找到达标的 npx 则复用，否则自动下载便携版 Node.js
启动命令 → 以伪终端（PTY）运行 npx -y @deepseek-ai/dsh web，内置终端实时显示输出
解析认证地址 → 从输出中提取带 token 的服务地址（而非裸端口），保证直接进入已登录界面
自动跳转 → 端口就绪后原生导航到认证 URL，窗口切换为 dsh 的 Web 界面
关闭窗口 → killpg 杀掉整个进程组，干净退出，不留后台残留

04 常见问题

装不上、打不开、跑得慢？大概率是这几个。

macOS 提示「已损坏，无法打开」怎么办？

这是 macOS 给网络下载应用加的隔离标记，应用本身并没有损坏。打开「终端」执行：
sudo xattr -cr /Applications/dsh-desktop.app
输入开机密码后再双击打开即可。

首次启动特别慢，是卡住了吗？

不是。首次运行需要下载 Node 运行环境（如缺失）和 dsh 依赖包，视网络情况可能需要几分钟；窗口内终端会实时显示进度，状态栏也有"仍在工作中"的心跳提示。之后再启动会直接复用缓存，秒级完成。

提示端口 3080 被占用？

一般是上次未正常退出留下的残留进程，应用会尝试自动清理。若仍提示占用，可在终端执行 lsof -iTCP:3080 -sTCP:LISTEN 找到 PID 后 kill -9 <PID>，再重开应用。

怎么升级到新版本？

点击窗口标题栏的「检查更新」即可：应用会自动从 GitHub Releases 下载对应平台的安装包，经 minisign 签名校验后原地替换，按提示重启即生效。离线时自动跳过检查，不影响使用。

没有 Node.js 能用吗？

可以。应用会自动下载一份便携版 Node.js 到 ~/.cache/dsh-desktop，不需要管理员权限，也不改动系统环境。若本机已有 Node ≥ v22.15，则优先复用系统版本；还可用环境变量 DSH_NPX 指定自定义 npx 路径。
